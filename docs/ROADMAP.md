# ROADMAP - llama-sycl-studio 网关能力演进

> 目标：从"进程管理器 + 转发器"升级为**带健康语义的模型网关**。
> 原则：单机单卡（NUC12 / Arc A770M）场景优先，不做多副本/多租户等用不上的企业级能力。
> 状态标记：⬜ 待办 / 🔄 进行中 / ✅ 完成

---

## v0.8 — 网关健康内核（第一批）

**定位**：让网关能"感知"实例的真实健康状态，异常可发现、可自愈、可优雅停机。

| # | 能力 | 说明 | 状态 |
|---|---|---|---|
| M1 | 实例状态机 | running / degraded（进程活但 /health 不通）/ stopped 三态，HTTP 级探活 | ✅ |
| M2 | 转发前探活 | chat_proxy 转发前快速 GET /health（短超时），失败返回明确错误 | ✅ |
| M3 | 自愈重启 | 探测异常（进程死 / /health 连续 N 次失败）自动拉起 + 可选飞书通知 | ✅ |
| M4 | 优雅停止 | stop 时先标记 draining，排空在途流式请求再杀进程 | ✅ |

**验收标准**：
- 手动 kill 实例进程 → 前端状态在 ≤30s 内变为 stopped（或自动恢复 running）
- 模拟 /health 不通 → 前端显示 degraded，转发返回 503 而非挂起
- 停止带在途请求的实例 → 当前流正常结束，新请求被拒

## v0.9 — 可观测性（第二批）

**定位**：请求级指标 + 心跳聚合面板 + 主动告警。

| # | 能力 | 说明 | 状态 |
|---|---|---|---|
| M5 | 请求级 metrics | 延迟 / token 吞吐 / QPS，**修复流式 token 未计入 bug** | ✅ |
| M6 | 心跳聚合 API | /api/gateway/health 聚合所有实例状态，Monitor 页显示心跳 + 最后探测时间 | ⬜ |
| M7 | 告警推送 | 实例异常 → 飞书消息通知（复用 lark 通道） | ⬜ |

**验收标准**：
- 统计页流式请求的 input/output token 与真实一致
- Monitor 页每实例显示 状态/端口/pid/心跳时间/探活延迟
- 实例崩溃触发飞书通知（可在设置中开关）

## v1.0 — 流量与资源控制

**定位**：多用户/多请求场景下的保护机制。

| # | 能力 | 说明 | 状态 |
|---|---|---|---|
| M8 | 并发控制 | per-model 最大并发，超出返回 429 或排队（可配置） | ⬜ |
| M9 | 显存感知调度 | 启动前查 xpu-smi 剩余显存，不足则拒绝并提示（防 OOM） | ⬜ |
| M10 | 预热 | 可选：容器启动时自动加载指定模型 | ⬜ |

**验收标准**：
- 并发超限请求收到 429 + 明确文案
- 显存不足时启动被拒，前端展示剩余/需要显存
- 预热配置生效，容器启动即加载目标模型

## 不做清单（单机自用场景明确排除）

- 多副本负载均衡 / 滚动更新 / canary —— 单卡单实例无意义
- 多租户权限隔离 / 按 key 配额 —— 单人/小团队自用
- 成本核算 / 账单 —— 无计费诉求
- 内容审核 —— 本地自用
